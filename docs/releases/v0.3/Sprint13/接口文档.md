# 行情数据服务接口文档

> 代码：`data_service/`
> 对照：[Sprint13 迭代文档](./迭代文档.md)
> 进程：`python -m app`，默认监听 `0.0.0.0:18080`

本文描述当前进程实际提供的 HTTP 接口。管理页面、调度和终止是后来加在同一进程上的，路径和字段以 `data_service/app/main.py` 为准。

## 1. 约定

| 项 | 规则 |
|---|---|
| 基址 | `http://<主机>:18080`。启动参数 `--host`、`--port` 可改 |
| 数据格式 | 除 Arrow 日线外，请求和响应都是 JSON，UTF-8 |
| 日期 | `YYYYMMDD`，闭区间。`2024-01-02` 会返回 422 |
| 时间 | 任务的 `started_at`、`finished_at` 是 UTC，形如 `2026-11-04T01:26:00+00:00`。收盘和调度按上海时间 |
| 鉴权 | 当前读接口和管理接口都不校验调用方密钥。部署时只放在可信任网络里 |
| 写入 | 同一进程里同时只跑一个拉取或一个备份。查询会等待这把写锁 |
| 任务 | 任务只留在内存里。进程重启后 `job_id` 失效，库里已经写入的行还在 |

错误体有两种。业务拒绝是字符串：

```json
{"detail": "start must be YYYYMMDD"}
```

请求体字段不合法时，FastAPI 返回字段列表，HTTP 状态码仍是 422。

| 状态码 | 含义 |
|---|---|
| 200 | 查询或设置已完成 |
| 202 | 拉取或备份已在后台开始 |
| 404 | 行业代码或任务不存在 |
| 409 | 已有任务在跑，或当前没有可终止的拉取 |
| 422 | 参数或请求体不合法 |
| 503 | `/health` 读不到库 |

日线类接口的 `format` 默认 `json`，响应为 `{"rows": [...]}`。`format=arrow` 时响应体是 Arrow IPC stream，`Content-Type` 为 `application/vnd.apache.arrow.stream`。其他值返回 422。

## 2. 页面与健康检查

### `GET /` 与 `GET /admin`

返回管理页面 HTML。两个路径内容相同。页面启动时已经读入内存，改 `data_service/app/static/admin.html` 后需要重启进程。

### `GET /health`

库能打开时返回：

```json
{"status": "ok"}
```

打不开时返回 503，`detail` 为 `database is not readable`。

## 3. 读接口

停牌日没有日线行。查询不补空行。

### `GET /v1/coverage`

无参数。返回各表行数和日期范围。`sw_industry` 没有日期列，`min_date` 和 `max_date` 为 `null`。

```json
{
  "tables": [
    {"table": "daily_bar", "rows": 1200, "min_date": "20240102", "max_date": "20241101"}
  ]
}
```

表名顺序：`daily_bar`、`adj_factor`、`sync_trade_date`、`trade_cal`、`index_daily`、`margin`、`stock_limit_status`、`index_weight`、`fut_daily`、`stocks`、`sw_industry`、`sw_industry_member`、`sync_step_state`。

### `GET /v1/calendar`

| 参数 | 必填 | 说明 |
|---|---|---|
| `start` | 是 | 起始日期 |
| `end` | 是 | 结束日期 |

只返回开市日，升序。

```json
{"start": "20240101", "end": "20240131", "dates": ["20240102"]}
```

### `GET /v1/stocks`

| 参数 | 必填 | 说明 |
|---|---|---|
| `list_status` | 否 | 逗号分隔，会转成大写。常用 `L` 在市、`D` 退市、`P` 暂停上市。不传则返回全部 |

按 `ts_code` 升序。

```json
{
  "stocks": [
    {
      "ts_code": "000001.SZ",
      "symbol": "000001",
      "name": "平安银行",
      "area": "深圳",
      "industry": "银行",
      "market": "主板",
      "list_date": "19910403",
      "list_status": "L",
      "delist_date": null
    }
  ]
}
```

### `GET /v1/bars`

单只股票的日线。必须带代码和日期窗口。

| 参数 | 必填 | 说明 |
|---|---|---|
| `ts_code` | 是 | 如 `000001.SZ`。空白返回 422 |
| `start` | 是 | 起始日期 |
| `end` | 是 | 结束日期 |
| `adjust` | 否 | `none`、`qfq`、`hfq`。默认 `none` |
| `format` | 否 | `json` 或 `arrow`。默认 `json` |

价格列在复权时乘以比例，成交量、成交额不复权。

| `adjust` | 比例 |
|---|---|
| `none` | 1。`change`、`pct_chg` 用库内原值 |
| `qfq` | 当日复权因子 / 窗口内不晚于 `end` 的最新因子 |
| `hfq` | 当日复权因子 / 该股票最早一条复权因子 |

因子缺失或分母为 0 时，该行比例为 1。复权后的涨跌额、涨跌幅按复权价重算。

每一行字段：`ts_code`、`trade_date`、`open`、`high`、`low`、`close`、`pre_close`、`change`、`pct_chg`、`vol`、`amount`、`ah_vol`、`ah_amount`、`adj_factor`。

```json
{
  "rows": [
    {
      "ts_code": "000001.SZ",
      "trade_date": "20240102",
      "open": 10.0,
      "high": 10.5,
      "low": 9.8,
      "close": 10.2,
      "pre_close": 10.0,
      "change": 0.2,
      "pct_chg": 2.0,
      "vol": 100000.0,
      "amount": 102000.0,
      "ah_vol": null,
      "ah_amount": null,
      "adj_factor": 1.5
    }
  ]
}
```

### `GET /v1/indexes/{ts_code}/bars`

指数日线。`start`、`end` 必填，`format` 可选。

字段：`ts_code`、`trade_date`、`open`、`high`、`low`、`close`、`pre_close`、`change`、`pct_chg`、`vol`、`amount`。

`399001.SZ` 的成交量和成交额改用 `399107.SZ` 同日值；`399006.SZ` 改用 `399102.SZ`。对应行不存在时仍用指数自身的量额。

### `GET /v1/index-weights`

| 参数 | 必填 | 说明 |
|---|---|---|
| `index_code` | 是 | 如 `000300.SH` |

只返回该指数最新一个 `trade_date` 的成分。没有记录时 `as_of` 为 `null`，`members` 为空数组。

```json
{
  "index_code": "000300.SH",
  "as_of": "20240102",
  "members": [{"con_code": "000001.SZ", "weight": 2.5}]
}
```

### `GET /v1/industries`

无参数。申万行业节点，按层级和行业代码排序。

```json
{
  "industries": [
    {
      "index_code": "801010.SI",
      "industry_code": "110000",
      "parent_code": "0",
      "level": "L1",
      "name": "农林牧渔",
      "is_pub": "Y",
      "src": "SW2021"
    }
  ]
}
```

### `GET /v1/industries/{code}/members`

`code` 可以是 `industry_code` 或 `index_code`。两边都能匹配时优先行业代码。找不到返回 404，`detail` 为 `industry not found`。层级不是 `L1`、`L2`、`L3` 时同样 404。

```json
{
  "index_code": "801010.SI",
  "industry_code": "110000",
  "level": "L1",
  "name": "农林牧渔",
  "members": [
    {
      "ts_code": "000001.SZ",
      "l1_code": "110000",
      "l2_code": "110100",
      "l3_code": "110101",
      "in_date": "20200101"
    }
  ]
}
```

`L1` 按 `l1_code` 过滤，`L2`、`L3` 分别按 `l2_code`、`l3_code`。

### `GET /v1/margin`

| 参数 | 必填 | 说明 |
|---|---|---|
| `start` | 是 | 起始日期 |
| `end` | 是 | 结束日期 |

按日期、交易所排序。金额字段缺失时为 `null`。

```json
{
  "rows": [
    {
      "trade_date": "20240102",
      "exchange_id": "SSE",
      "rzye": 1.0,
      "rqye": 2.0,
      "rzrqye": 3.0
    }
  ]
}
```

`exchange_id` 为 `SSE` 或 `SZSE`。

### `GET /v1/futures/{ts_code}/bars`

读取库里已有的股指期货收盘价。`start`、`end` 必填，`format` 可选。字段只有 `ts_code`、`trade_date`、`close`。当前流水线不再拉取这张表，新行来自桌面库导入。

### `GET /v1/limits`

| 参数 | 必填 | 说明 |
|---|---|---|
| `trade_date` | 是 | 单个交易日 |

```json
{
  "rows": [
    {"ts_code": "000001.SZ", "trade_date": "20240102", "limit_status": 2}
  ]
}
```

`limit_status` 原样返回库内整数。当前流水线不再拉取涨跌停，新行来自桌面库导入。

## 4. 管理接口

### `GET /v1/admin/status`

管理页面使用的整页状态。无参数。

```json
{
  "global": "stale",
  "last_closed_trade_date": "20241101",
  "calendar_error": null,
  "steps": [],
  "has_token": true,
  "boards": {
    "sse_main": 0,
    "szse_main": 0,
    "chinext": 0,
    "star": 0,
    "bse": 0,
    "other": 0,
    "total": 0
  },
  "job": null,
  "schedule": {"enabled": true, "hour": 17, "minute": 0},
  "access_urls": ["http://192.168.5.6:18080/"]
}
```

`global`：

| 值 | 含义 |
|---|---|
| `init` | 任一必做步骤尚未初始化 |
| `stale` | 必做步骤都已初始化，但至少一步相对最近收盘日不是最新 |
| `fresh` | 必做步骤都已初始化且都是最新 |
| `running` | 内存里有状态为 `running` 或 `cancelling` 的任务，覆盖上面三种 |

`last_closed_trade_date` 是上海时间 17:00 之后才计入当天的最近开市日。17:00 之前当天不算已收盘。日历为空时为 `null`。

`boards` 只统计 `list_status = L`。创业板、科创板、北交所按 `market` 归类。主板和中小板再按 `.SH`、`.SZ` 分成沪市主板、深市主板，其余进 `other`。

`access_urls` 是本机非回环 IPv4 加上当前请求端口，供局域网打开管理页。

`job` 是最近一个内存任务，没有则为 `null`。字段见下文「任务对象」。失败任务会写到对应步骤的 `error`，并把该步骤 `status` 改成 `failed`。

每个步骤：

| 字段 | 说明 |
|---|---|
| `id` | 步骤标识，可作为 `POST /v1/admin/pipeline` 的 `step_id` |
| `ordinal` | 展示序号 |
| `title` | 展示名称 |
| `parent` | 历史日线挂在 `daily_bar` 下，其余为 `null` |
| `required` | 必做步骤参与 `global`；历史分段为 `false` |
| `status` | `not_started`、`stale`、`fresh`、`running`、`failed` |
| `initialized` | 是否已经有过可用数据 |
| `fresh` | 是否追到当前判定边界 |
| `coverage_start` / `coverage_end` | 已覆盖日期，没有则为 `null` |
| `detail` | 中文摘要，如开市日数量、缺几天 |
| `error` | 最近失败信息，否则 `null` |

当前步骤：

| 序号 | `id` | 名称 | 必做 |
|---|---|---|---|
| 1 | `trade_cal` | 交易日历 | 是 |
| 2 | `index_daily` | 大盘指数与宽基指数日线 | 是 |
| 3 | `stock_list` | 上市股票列表 | 是 |
| 4 | `daily_bar` | 股票日线与复权，自 `20240101` 至最近收盘日 | 是 |
| 4.1–4.8 | `daily_bar_hist_2021` 至 `daily_bar_hist_2000` | 更早的三年一段历史日线，直到 `20000101` | 否 |
| 5 | `delisted` | 退市股票列表 | 是 |
| 6 | `index_weight` | 宽基指数成分股 | 是 |
| 7 | `sw_industry` | 行业分类与成分股 | 是 |
| 8 | `margin` | 两融 | 是 |

历史分段的 `id` 按起点年份命名，顺序是 `daily_bar_hist_2021`、`daily_bar_hist_2018`、`daily_bar_hist_2015`、`daily_bar_hist_2012`、`daily_bar_hist_2009`、`daily_bar_hist_2006`、`daily_bar_hist_2003`、`daily_bar_hist_2000`。

`index_daily`、`daily_bar`、`margin` 的 `initialized` 一旦变为真就保持，即使后来判定不再 fresh。

### `PUT /v1/admin/schedule`

写入 `DATA_DIR/schedule.json`。调度线程约每 60 秒看一次，到点且开关打开时，若最近收盘日尚未补齐，就启动与全量按钮相同的流水线。

```json
{"enabled": true, "hour": 18, "minute": 30}
```

| 字段 | 说明 |
|---|---|
| `enabled` | 布尔值 |
| `hour` | 17–23 |
| `minute` | 0–59 |

成功原样返回保存后的三个字段。小时或分钟超出范围返回 422。文件还不存在时，默认开关来自环境变量 `SCHEDULER_ENABLED`（不是 `0` 则打开），时刻是 17:00。

手动终止后，本次收盘日的自动调度会停住。下一次手动 `POST /v1/admin/pipeline`，或收盘日变了，调度才恢复。

### `POST /v1/admin/pipeline`

后台拉取。请求体可以省略，省略时按上面的步骤顺序全部执行。

```json
{"step_id": "daily_bar", "max_days": 5}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `step_id` | 否 | 只跑这一步。未知标识返回 422 |
| `max_days` | 否 | 大于等于 1。只截断日线步骤当天要补的天数，其他步骤忽略 |

成功返回 202 和任务对象。已有拉取或备份在跑时返回 409，`detail` 为 `a pipeline or backup is already running`。

没有 `TUSHARE_TOKEN` 时任务仍会创建，随即变成 `failed`，`errors` 含 `TUSHARE_TOKEN is not set`。

日线步骤跳过水位已完整的交易日。`max_days` 小于剩余天数时，这一步不会标成已同步。单日只有日线和复权都写入才算完整；失败日保留在待补列表里。

流水线写入交易日历、指数日线、股票列表、日线、复权因子、退市标记、指数权重、申万行业和两融。它不请求涨跌停，也不请求股指期货。

### `POST /v1/admin/pipeline/cancel`

无请求体。给当前 `running` 的拉取打上终止标记，并立刻返回该任务，此时 `status` 为 `cancelling`。

终止发生在步骤之间、每个日线交易日之间，以及 Tushare 限速等待处。已经发出的那一次 Tushare 调用会走完，已经写入的交易日保留。完成后任务变为 `cancelled`，`detail` 为 `已终止`。

没有正在跑的拉取时返回 409，`detail` 为 `no pipeline is running`。备份不能用这个接口终止。

### `GET /v1/admin/jobs/{job_id}`

返回任务对象。进程重启后，或 `job_id` 不存在时，返回 404，`detail` 为 `job not found`。

任务对象：

| 字段 | 说明 |
|---|---|
| `id` | 32 位十六进制 |
| `kind` | `pipeline` 或 `backup` |
| `status` | `running`、`cancelling`、`cancelled`、`failed`、`done` |
| `step_id` | 当前或最后一步，尚未进入步骤时为 `null` |
| `current_date` | 日线步骤正在处理的交易日 |
| `done_days` | 日线步骤已经计入的天数 |
| `detail` | 步骤摘要 |
| `errors` | 失败原因列表，成功时为空数组 |
| `started_at` | UTC 开始时间 |
| `finished_at` | UTC 结束时间，未结束为 `null` |
| `result` | 备份成功时有路径；拉取成功为 `null` |

### `POST /v1/admin/backup`

无请求体。先 `CHECKPOINT`，再把各表导出为 Parquet，然后复制库文件。成功返回 202 和任务对象。完成后：

```json
{
  "result": {
    "db_copy": "E:/Trading/trading-zone-electron/data_service/data/backups/market-20261104T012600Z.duckdb",
    "parquet_dir": "E:/Trading/trading-zone-electron/data_service/data/export/20261104T012600Z",
    "verified": true
  }
}
```

路径随 `DATA_DIR` 变化。`verified` 表示副本能以只读方式打开并读到 `schema_version`。已有拉取或备份时返回 409。

## 5. 调用示例

```bash
curl "http://127.0.0.1:18080/health"
curl "http://127.0.0.1:18080/v1/bars?ts_code=000001.SZ&start=20240102&end=20240131&adjust=qfq"
curl -X POST "http://127.0.0.1:18080/v1/admin/pipeline" \
  -H "Content-Type: application/json" \
  -d "{\"step_id\":\"daily_bar\",\"max_days\":1}"
curl -X POST "http://127.0.0.1:18080/v1/admin/pipeline/cancel"
```

局域网访问时把 `127.0.0.1` 换成 `GET /v1/admin/status` 里的地址。Windows 若连接超时，需要放行对应 TCP 端口。
