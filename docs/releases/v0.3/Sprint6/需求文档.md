# 需求概述
## 1.交易记录表管理
- 交易记录表用于实际交易过程中产生的交易事件的管理
- 具体表单的内容见图片：docs\releases\v0.3\Sprint6\交易记录表.png
- 呈现效果
  - 新建交易管理表页面，管理表页面展示交易记录列表，列表的每一行对应一条交易记录表单。列表上方是列表的工具栏，放过滤条件和创建按钮
  - 表单右上角是创建新表单的按钮，按钮文字由加号图标和文字创建构成
  - 创建表单使用MUI的Full-screen dialogs组件
  - 交易表单状态(不在创建时显示)
    - 表单被创建时没有买卖记录->计划中
    - 表单被创建并添加了买卖记录，并还有持仓-> 进行中
    - 表单被创建并添加了买卖记录，并持仓已经为0 -> 已完成
  - 表单支持修改
    - 入口在列表的每一行最后加入边际图标按钮，点击弹出创建表单同款dialog，数据回填表单。
    - 修改限制：计划中和进行中可以修改，已完成交易不能修改
- 表单：在图片中的表单基础上分段设计
  - 息费：用于下面步骤的自动计算
    - 佣金：缺省0.05%，必填
    - 印花税：缺省0.05%，必填
    - 其他费用和：缺省0
  - 交易分析：还没进行交易时的计划，创建时可输入，编辑模式变为不可修改项
    - 标的代码扩展为名称+代码，支持输入模糊查询，属性命名为`标的`。必填。
    - 方向：做多/做空。必填。
    - 交易类型：左侧交易/右侧交易
    - 明确进场理由：用Multiline制作，占2列
    - 信息来源机构和信息来源个人。必填。
    - 进场价。必填。
    - 进场时间。必填。
    - 入场指令，单选：限价单/市价单
    - 进场费用：需要备注提示`进场费用=佣金+滑点`：加入自动计算的checkbox，缺省选中，此时费用的输入框不可输入。取消自动计算，可以手动填写
    - 原地出场费用：备注提示`以入场价出场产生的费用`。加入自动计算的checkbox，缺省选中，此时费用的输入框不可输入。取消自动计算，可以手动填写
    - 盈亏平衡价: 备注提示`加入买入和原地卖出费用的费用后得出的价格`。加入自动计算的checkbox，缺省选中，此时费用的输入框不可输入。取消自动计算，可以手动填写。算法是`以X价格卖出的总额，减去买卖产生的交易费用，减去进场价的总额等于0`
  - 投后管理：可以重复修改，直到交易已完成。
    - 投后管理在初次创建表单时可以不添加买卖记录
    - 进场理由是否仍成立checkbox
    - 交易数据：修改时自动计算，默认为无持仓状态，根据买入卖出自动计算持仓数据
      - 持仓平均成本
      - 持仓数量
      - 交易产生的总费用
      - 净收益：根据最新K线数据、持仓情况和交易费用计算持仓的收益。
    - 买入管理
      - `买入`按钮，支持分笔买入
      - 买入记录条目由下面几个部分组成：
        - 成交时间
        - 成交价
        - 成交费用
        - 入场首日盈亏：支持使用应用内部的OHLC数据自动计算，也可以手动输入
      - 添加好的买入记录用列表呈现
    - 卖出管理
      - `卖出`按钮，支持分笔卖出
      - 卖出记录条目由下面几个部分组成：
        - 成交时间
        - 成交价
        - 成交费用
- 交易记录列表：
  - 包含列按照从左到右的顺序：
    - 标的名称/代码+展开图标（用于在行内嵌套的展开详情）
    - 进场时间（交易分析）
    - 方向
    - 交易类型
    - 交易表单状态
    - 净盈亏
    - 编辑按钮
  - 行内详情，点击标的名称后面的展开图标展开
- 列表过滤功能，支持：
  - 进场时间（交易分析）
  - 标的名称/代码
  - 方向
  - 交易类型
  - 交易表单状态
  - 净盈亏
- 其他注意项
  - 因为这个应用会在21：9的超宽屏上使用，设计表单宽度的时候，不能默认使用全屏宽度，在设计时考虑表单使用固定宽度+居中的布局方式
