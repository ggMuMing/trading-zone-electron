# 问题汇总
## 1.数据获取
- 设置页面，选择更新窗口，点击更新数据，更新成分股，更新行业分类三个按钮，完成初始化数据和更新数据两类操作。
- 问题一：初始化数据需要三个按钮
- 问题二：`更新数据`按钮背后的初始化流程不透明，除了一个进行中的进度条和描述，没有过程追踪和记录。初始化结束后，初始化结果得出的结论不够具体。
- 问题三：整个初始化数据的流程不系统。不同数据的获取流程是随着开发新需求而增加的，所有的流程之间的先后关系没有经过梳理。
- 问题四：主动选择更新窗口的日期间隔更新数据，无法追踪数据当前的状态，只能靠使用者自我记忆自我约束。

## 2.数据清洗
- 需要增加`退市股票`的分类。包括新的表，图表页面新的分类。
- 加入股票列表的更新功能，补充新上市的股票，剔除退市的股票到退市列表

# 迭代目标
## 1.重构更新数据功能
依据`Sprint9数据架构分析.md`文档

### 功能
UI参考：`E:\Trading\trading-zone-electron\docs\releases\v0.2\Sprint9\更新数据卡片.png`

取消设置页的用户自选更新窗口。主路径不再让使用者填写起止日。自定义区间若以后开放，只放在「自定义管理数据」，不参与主状态机。

### 数据拉取方式
分为`全量拉取`和`分批拉取`两种，区间写死在代码里，不由 UI 选择。

- `全量拉取`：外沿为`2000-01-01～最近已收盘开市日`。具体品种按上市日裁剪，不强制从 2000 对齐。
- `分批拉取`：仅股票日线。默认段为`2024-01-01～最近已收盘开市日`；更早历史按年份边界切成闭区间子步骤（4.1、4.2…），倒序、一次解锁一步，手动执行。

### 状态机

共享三态，每步自己回答两问。禁止用「各步时间间隔粗暴对比交易日历」作为统一判据。

**步骤两问**

1. **是否已初始化**（单向闩锁）：这份数据的目标底盘有没有曾经拉全过。一旦为真，不因之后缺最新一天而退回未开始。
2. **是否最新**：在已初始化的前提下，相对该步自己的新鲜度标尺，现在过不过期。

由两问推出步骤三态：

| 已初始化 | 是否最新 | 步骤状态 |
|-|-|-|
| 否 | — | 未开始 |
| 是 | 否 | 待更新 |
| 是 | 是 | 最新 |

另两个运行态，不参与「是否初始化」的回溯：

- **进行中**：该步或全局流水线正在拉数
- **失败 / 部分完成**：额度用尽、单日 `partial`、接口失败。断点续跑时仍视为已初始化（若闩锁已置位）或未开始（若底盘从未拉全），UI 需能看出来源失败而不是空白

**统一接口，分步实现**

步骤状态由同一套接口算出，每步提供自己的实现，避免九段散落的日历比对：

- `initialized()`：闩锁是否已置位
- `fresh()`：按该步口径是否最新
- 覆盖区间：给步骤列表展示的起始日～截至日（没有数据则空）

打开本页时：

1. 只自动刷新步骤 1 交易日历，不自动拉其它数据。Token / 网络失败时保留本地日历，步骤 1 标待更新，其它步仍用本地日历继续判定，整页不卡死。
2. 再调一个统一状态接口，内部按各步专属逻辑返回步骤态和全局态。
3. 日频步骤对齐「最近一个已收盘开市日」，不要把交易时段里「今天还没收盘」判成待更新。

**全局状态只折叠必做步骤**

必做步骤：`1、2、3、4（默认段）、5、6、7、8、9`。  
可选步骤：`4.1` 及更早的日线历史子步。可选步只影响自己那一行，不改主按钮文案。

| 必做步骤情况 | 全局状态 |
|-|-|
| 存在未开始 | 初始 |
| 均已初始化，且存在待更新或失败 / 部分完成 | 待更新 |
| 均为最新 | 最新 |
| 主流程正在执行 | 进行中 |

派生步骤（退市列表）不独立对日历：步骤 3 与步骤 4 默认段都最新则它最新，否则跟随较落后的一侧。

### 操作按钮
三种文案对应全局状态（进行中时按钮不可用，显示进度）：

- 初始：`初始化数据`。从第一个未完成的必做步骤接着跑，已完成的步跳过。支持断点继续。
- 待更新：`更新数据`。只补过期或有空洞的必做步骤。支持断点更新。
- 最新：`数据已更新`，按钮不可用。下一已收盘开市日之后打开页面，应变回待更新。

历史子步（4.1…）用行内按钮，不做进主按钮。子步骤按倒序一个一个执行，做完一步再放开下一步。

- 清除所有数据：和当前保持一致
- 自定义管理数据：暂时不可用，不参与主状态机

### 步骤列表
按下方拉取步骤列出。覆盖列展示**日期间隔**（起始日期～截至日期），不再只展示截至日期。

### 股票日线水位必须保留
本迭代**不得删除**股票日线专属水位表 `sync_trade_date`（按日 `complete`）。它不作为步骤列表里的独立一步（不是一种行情数据），但步骤 4 / 4.1 的断点续拉、跳过已完成日、空洞检测、初始化闩锁、是否最新，全部以这张表为准。

- 交易日历回答「哪些天该有行情」
- 日线水位回答「哪些天已经拉过」
- 禁止改成只比较 `daily_bar` 的 `MAX(trade_date)` 来代替水位

其它全量类数据（日历、指数、期指、两融）不建水位表，用各自覆盖区间判定。

### 数据拉取步骤与专属判定

|步骤|标题|拉取|必做|判定口径|
|-|-|-|-|-|
|1|交易日历|全量|是|已初始化：本地有开市日清单。是否最新：覆盖到最近已收盘开市日（含休市调整）。打开页面自动刷新，失败则降级用本地日历|
|2|大盘指数&宽基指数日线数据|全量|是|按品种上市日裁剪目标区间。已初始化：曾经拉全过该生命周期。是否最新：右端对齐最近已收盘开市日。无水位表|
|3|上市股票列表|快照|是|已初始化：名单表非空。是否最新：相对应刷新时机（随更新流程 / 已收盘日）是否过期。不对齐交易日序列|
|4|股票日线：日线数据+复权数据+涨跌停|分批，默认 `2024-01-01～最近已收盘`；**保留 `sync_trade_date` 水位表**|是|见下方「步骤 4 日线」。判定和续跑只认水位，不认截至日|
|4.1|股票日线：`[2021-01-01～2024-01-01)`|分批闭区间，同一张水位表|否|已初始化与是否最新合并为：该闭区间内每个开市日水位均为 complete。拉全后不因「今天」过一天而变待更新。行内按钮，倒序解锁。后续更早历史块按同样年份边界追加|
|5|退市股票列表|由 3+4 筛选|是|派生。不独立对比交易日历。3 与 4 默认段都最新则本步最新|
|6|宽基指数成分股列表|按月|是|已初始化：有过快照。是否最新：最近一个应有的月末快照在。不对齐每个交易日|
|7|行业分类&成分股|快照|是|同步骤 3，看快照是否过期，不是日历匹配|
|8|股指期货主力合约收盘价历史数据|全量|是|合约上市晚则从实际可取日起算，不要对 2000。已初始化：该可取日历曾经拉全。是否最新：右端对齐。无水位表|
|9|两融历史数据|全量|是|已初始化：两市历史底盘曾经拉过。是否最新：允许两市公布差一天；两市都补齐才算对齐。无水位表|

**步骤 4 日线（默认段）**

- **必须保留**现有 `sync_trade_date` 水位表。按日 `complete` 才能跳过、续跑、发现空洞。禁止只比较 `MAX(trade_date)`，也禁止用全局截至日期法替换这张表。
- **未开始**：默认段内还没有 complete 日，或左端底盘（`2024-01-01` 起第一个开市日）从未覆盖。
- **初始化完成（闩锁）**：水位上 `[2024-01-01, 当时最近已收盘开市日]` 全部 `complete` 时置位（如 `daily_bar_init_done`）。此后缺最新一天**不得**清掉闩锁。
- **是否最新**：闩锁为真，且 `[2024-01-01, 最近已收盘开市日]` 仍无空洞、右端已对齐。缺一天或出现空洞 → 待更新，不是未开始。
- 断点续拉只问水位，不问闩锁。倒序补历史时尤其不能用截至日等于窗口右端来宣布该段最新。
