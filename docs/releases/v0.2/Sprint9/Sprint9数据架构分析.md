# 从第一次打开应用的状态开始走通数据架构
## 1.初始保存的数据
代码中保存：
- 大盘指数列表
- 宽基指数列表

第一次打开时只有上面的名单，还没有交易日历，也没有行情。日历和行情从第 2 节开始拉。

## 2.初次拉取数据
2.1、交易日历：先拿到目标时间范围内的开市日清单。后面所有按日拉取都以日历为准，休市日不拉。
2.2、指数的日线数据一次性获取：从2000年到最新一天
2.3、上市股票列表
2.4、股票日线：
  - 日线数据+复权数据+涨跌停状态
  - 股票日线数据庞大，所以需要按开市日分批手动获取
2.5、同步水位：每完成一个开市日就记下「这一天已经拉全」。中断后从水位接着拉，已完成的日子跳过，不必从头来。
2.6、股票日线数据+上市股票列表筛选出`退市股票列表`
2.7、宽基指数成分股列表：按月查询
2.8、行业分类+成分股
2.9、股指期货主力合约收盘价的历史数据：从2000年到最新一天
2.10、两融余额历史数据：从2000年到最新一天

- 备注1：时间期限`从2000年到最新一天`是大的时间范围，具体品种的时间范围根据其具体的上市时间来计算。
- 备注2：交易日历回答「哪些天该有行情」；同步水位回答「哪些天已经拉过」。分批和增量都靠这两项配合。

## 3.更新数据
3.1、刷新交易日历到最新开市日（以及可能的休市调整），再决定今天该补哪些天
3.2、对照同步水位，只补尚未拉全的开市日；补完后更新水位
3.3、指数——大盘指数&宽基指数日线数据增量更新
3.4、每天检查股票列表的更新——追踪上市退市
3.5、股票日线的增量更新（走 3.2 的水位，不重拉已完成的日子）
3.6、基于3.4和3.5更新`退市股票列表`
3.7、更新宽基指数成分股列表：*成分股列表更新不频繁，但是需要每天查询*
3.8、更新行业分类的成分股：*同3.7*
3.9、更新股指期货主力合约收盘价
3.10、更新两融余额：*两市的两融余额公布时间不同，所以可能查出的两融可能只包含一个市场的，当两个市场都补全的时候，需要对齐*
